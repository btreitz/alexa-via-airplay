# CLAUDE.md

Guidance for humans and coding agents working on this repository.

## What this is

A bridge that exposes Amazon Echos as AirPlay 2 receivers. It runs in one Docker container
with host networking on a Linux machine in the user's home network. See
[README.md](README.md) for the pitch and [SETUP.md](SETUP.md) for setup, configuration
and the security model.

## How it works

1. **AirPlay in.** For every selected Echo the bridge runs a Shairport Sync instance
   (`src/airplay/receiver/`). Shairport writes PCM to a pipe and publishes playback events
   over MQTT to an in-process broker (`src/airplay/events/`).
2. **Audio pipeline.** PCM is read, level-metered and kept in a short history
   (`src/airplay/audio/pcm/`), encoded to MP3 by ffmpeg (`audio/mp3/encoder.ts`) and fanned
   out to HTTP clients (`audio/mp3/broadcaster.ts`). Filler sound (silence, chime) keeps the
   stream alive between tracks (`audio/filler/`).
3. **Start the Echo.** On play, the session manager (`src/bridge/session/`) asks Amazon,
   through `alexa-remote2` (`src/alexa/controller/`), to open the user's private Alexa
   skill on that Echo. Volume follows AirPlay via `bridge/session/volume/`.
4. **Skill hands out a link.** The skill code is generated by the bridge
   (`src/alexa/skill/index-js.ts`) and pasted by the user into the Alexa developer
   console. It answers with a signed, 60-second link to `/play.mp3` and reports playback
   events back to the same path.
5. **Public stream.** The Echo fetches the link through the user's public HTTPS URL
   (usually a Cloudflare Tunnel run by the user, not by this project). The public server
   (`src/public/server/`) checks signature, home IP and an active session, and answers
   every refusal with the same 404.
6. **Web UI and API.** A LAN-only HTTP server (`src/ui/`) serves the static Next.js export
   from `web/out` and a JSON API under `/api`. State lives in a JSON file in the data
   volume (`src/state/store.ts`).

`src/main.ts` starts everything; `src/app/wiring.ts` connects the parts.

## Layout

| Path           | Contents                                                                          |
| -------------- | --------------------------------------------------------------------------------- |
| `src/airplay/` | Shairport receivers, MQTT events, PCM/MP3 pipeline, host checks, Avahi/NQPTP      |
| `src/alexa/`   | Amazon control (`alexa-remote2`), device models, skill code and interaction model |
| `src/bridge/`  | The `Bridge` class, receiver pool, sessions, volume sync, speaker tests           |
| `src/public/`  | Public stream server, request signing, home-IP checks, public URL check           |

| `src/lib/`     | Small generic utilities (files, time, numbers, logging, supervised processes)     |
| `test/`        | Node test runner tests, mirroring `src/`                                          |
| `web/`         | Next.js 16 static export, shadcn/ui, Tailwind v4                                  |

## Commands

```bash
pnpm install
pnpm check          # format:check + typecheck + lint + test; run before every commit
pnpm format         # Prettier, writes in place
pnpm test           # backend tests only
pnpm build          # web UI into web/out
```

AirPlay and audio need Linux, Shairport Sync, NQPTP and ffmpeg, so they only run in the
container (`docker compose up -d --build`). The HTTP side runs on any machine:

```bash
pnpm build
DATA_DIR=./data RUN_DIR=/tmp/avb MANAGE_RECEIVERS=false pnpm start
```

UI with hot reload, against a running bridge:

```bash
UI_DEV_ORIGIN=http://localhost:3000 DATA_DIR=./data RUN_DIR=/tmp/avb MANAGE_RECEIVERS=false pnpm start
BRIDGE_URL=http://localhost:8098 pnpm dev:web
```

## Code conventions

- **TypeScript runs directly on Node ≥ 22.18** (type stripping, no build step for the
  backend). Only erasable syntax: no enums, no namespaces, no constructor parameter
  properties. Relative imports carry the `.ts` extension; type-only imports use
  `import type` / inline `type`.
- **One class per file.** Types go in the area's `types.ts`, constants in its
  `constants.ts`. Generic helpers go in `src/lib/`; helpers specific to one area go in a
  utility file inside that area.
- **Topic folders.** Files of the same concern share a folder instead of a name prefix:
  `audio/mp3/encoder.ts`, not `audio/mp3-encoder.ts`. The same applies to the web
  components.
- **Small functions and components.** Split a function when it gets long or does more than
  one thing; one React component per file.
- **No comments**, except where the code can't say it: license headers, `eslint-disable`
  lines, and non-obvious external constraints (the ffmpeg probe flags, the skill's ES5
  style).
- **Prettier** formats everything (`.prettierrc.json`, Tailwind classes sorted). ESLint
  runs with `eslint-config-prettier`.
- **Tests** live in `test/`, mirror the `src/` path and use `node:test`. Add or update
  tests with every behaviour change.
- **Web code** uses the `@bridge/*` alias to import backend types and pure helpers. Only
  import files that don't touch Node APIs; the web build runs in the browser. Web types go
  in `web/src/lib/types.ts`, constants in `web/src/lib/constants.ts`, derived data in
  `web/src/lib/`.

## Gotchas

- The generated skill code (`src/alexa/skill/index-js.ts`) must stay plain ES5-style
  JavaScript: the Alexa-hosted runtime is Node 16 and the console editor rejects modern
  syntax.
- Keep ffmpeg's `-probesize`/`-analyzeduration` flags; without them the Echo plays about
  5 seconds later.
- Host networking is required (mDNS and AirPlay ports). Docker Desktop on macOS or Windows
  can't run the AirPlay side.
- Every refusal on the public port must look the same (plain 404), so the port reveals
  nothing.
- Changing the stream URL format or signing breaks every pasted skill; the user would have
  to paste the code again.
- Amazon's API used by `alexa-remote2` is unofficial. Keep its version pinned.
- `compose.yaml` passes each user-facing environment variable explicitly (`VAR: ${VAR:-}`).
  A new variable must be added there and to `.env.example`; empty values count as unset.

## Never commit

Secrets, `.env`, the `data/` folder, Amazon cookies, signing secrets or
generated skill code containing a secret. The local `docs/` folder is ignored on purpose.
